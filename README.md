## 1. Business Problem

A B2B SaaS company selling CRM analytics software across
five global regions has reached a growth inflection point.
The sales organisation — five Account Executives managing
1,200 deals across 500 accounts over 24 months — operates
without a unified view of pipeline health, rep performance,
or customer retention risk.

Leadership cannot answer four questions that directly
affect revenue:

- **Where is revenue leaking in the pipeline?**
  Deals stall at Negotiation with no early-warning system.
- **Which customers are most likely to churn?**
  Customer Success has no churn score or LTV-weighted
  priority list.
- **Which reps are on track and which need intervention?**
  Quota attainment is tracked in spreadsheets, not a
  live system.
- **What is actually driving lost deals?**
  Loss reasons are logged inconsistently and never
  aggregated into a pattern.

PipelineIQ was built to answer all four questions from
a single analytics platform.

## 4. Requirements

### Functional Requirements
- Generate and clean realistic CRM data across 5 entities
- Calculate 13 executive KPIs from raw transactional data
- Produce 10 analytical output tables covering all business questions
- Deliver a PostgreSQL-compatible normalised schema (3NF)
- Provide 6 analytical views and 3 stored procedures
- Render a 5-tab interactive dashboard with no server dependency

### Non-Functional Requirements
- Dashboard must load locally without a web server
- All Python scripts must run end-to-end with one command
- SQL schema must be idempotent (safe to re-run)
- Data generation must be reproducible (fixed random seed)

## 7. Data Cleaning

All cleaning logic lives in `python/data_cleaning.py`.
A full audit log is written to
`data/processed/cleaning_audit.csv`.

| Table | Issues Addressed |
|-------|-----------------|
| companies | Null annual_revenue filled with median; churn_risk_band and ltv_band derived |
| deals | Negative deal values nulled; loss_reason cleared for non-lost deals; deal_size_band derived |
| contacts | Invalid email format flagged; names title-cased; full_name derived |
| activities | Duration outliers (>480 min) capped at 60; notes nulls filled |
| sales_reps | years_of_service derived from hire_date |

**Derived columns added:**
`churn_risk_band` · `ltv_band` · `deal_size_band` ·
`is_won` · `is_lost` · `is_open` · `year_month` ·
`full_name` · `years_of_service` · `is_positive`

## 8. SQL Analysis

All SQL lives in the `sql/` folder.

### Schema Design
- **Normalisation:** Full 3NF with 7 lookup tables
- **Referential integrity:** All FK relationships enforced
- **Constraints:** CHECK constraints on probabilities,
  deal values, churn scores, and stage consistency
- **Indexes:** 14 indexes covering all FK columns and
  high-frequency query paths

### Key Queries

**Pipeline health check (stored procedure):**
```sql
SELECT * FROM fn_pipeline_health();
```

**Rep performance by quarter:**
```sql
SELECT * FROM fn_rep_performance_by_quarter(2024, 1);
```

**High churn risk accounts:**
```sql
SELECT * FROM fn_churn_risk_alert(0.6);
```

**Monthly revenue trend:**
```sql
SELECT year_month, revenue, cumulative_revenue
FROM   vw_monthly_revenue
ORDER  BY year_month;
```

**At-risk accounts requiring immediate intervention:**
```sql
SELECT company_name, churn_score,
       customer_ltv, intervention_urgency
FROM   vw_at_risk_accounts
WHERE  intervention_urgency = 'IMMEDIATE'
ORDER  BY customer_ltv DESC;
```
